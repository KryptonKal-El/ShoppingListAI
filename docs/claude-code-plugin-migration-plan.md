# Migrating Concepture-Toolkit from OpenCode to a Claude Code Plugin

**Status:** Draft plan for review
**Date:** 2026-06-08
**Decision:** Package the entire Concepture-Toolkit as a single Claude Code **plugin** that can be toggled on/off via `/plugin`. Run it in parallel with the existing OpenCode `.opencode/` setup (no removal) until verified.

---

## 1. Goal & packaging decision

Today the toolkit is an OpenCode system split across two places:

- **Global toolkit** — `~/Documents/GitHub/Concepture-toolkit`, symlinked into `~/.config/opencode/` (`agents/`, `skills/`, `bin/`, `docs/`, `schemas/`). 20 agents, 35 skills, 4 schemas, stack templates, `AGENTS.md` + `TOOLKIT-CONVENTIONS.md`, and the `concepture-opencode` launcher with a project registry.
- **Per-project** — e.g. `gather/.opencode/agents/` (8 stack specialists), `AGENTS.md` (Specialists block), `opencode.json` (context7 MCP), and `docs/` workflow state (`prd.json`, `session-state/`, `session-locks.json`, `progress.txt`).

**Target:** the global toolkit becomes **one Claude Code plugin** (`concepture-toolkit`), served from a **local marketplace** living in the existing toolkit git repo. The user installs once and toggles it on/off with `/plugin enable|disable concepture-toolkit@concepture`. Per-project stack specialists continue to live in each project's `.claude/agents/`, generated by the plugin's `project-bootstrap` skill from bundled templates — exactly mirroring how `.opencode/agents/` are seeded today.

Why a plugin (vs. symlinking `~/.claude`):
- Single on/off switch, versioned, no manual symlink management.
- Bundles agents + skills + commands + hooks + MCP in one unit.
- Survives across all projects on the machine without per-project setup.

## 2. Concept mapping (OpenCode → Claude Code)

| OpenCode | Claude Code | Notes |
|---|---|---|
| `mode: subagent` agents (routers, critics, specialists, Explore) | **Subagents** in plugin `agents/*.md` | Frontmatter translated; see §5 |
| `mode: primary` agents (Builder, Planner, Toolkit) | **Slash commands** in plugin `commands/*.md` | Primaries drive the main loop & spawn subagents — only the main thread can. See §4 |
| `skills/<name>/SKILL.md` (read by absolute path) | **Skills** in plugin `skills/<name>/SKILL.md` | Native, auto-discovered by `description`. Path-read hack is replaced — see §6 |
| `~/.config/opencode` symlinks to toolkit | **Plugin install** from local marketplace | `${CLAUDE_PLUGIN_ROOT}` resolves bundled files at runtime |
| `AGENTS.md` (toolkit, global registry) + `TOOLKIT-CONVENTIONS.md` | Bundled reference files in the plugin (read by the Toolkit command/skills) | Not auto-loaded; referenced via `${CLAUDE_PLUGIN_ROOT}` |
| Project `AGENTS.md` (Specialists block) | **`CLAUDE.md`** auto-loads; keep `AGENTS.md` as the data file the Builder skill reads | Reconcile gather's short `CLAUDE.md` with its long `AGENTS.md` (§7) |
| `opencode.json` → `mcp.context7` | Plugin `.mcp.json` (or project `.mcp.json`) | context7 is a remote MCP — trivial port |
| `concepture-opencode` launcher (project picker, env, toolkit-root) | Mostly **unnecessary** (you `cd` + run `claude`). Optional thin wrapper for the env-file + project picker | Plugin auto-resolves; no toolkit-root math needed |
| `schemas/`, `templates/`, `docs/` state | **Bundled in plugin** (schemas, templates) / **unchanged** (per-project `docs/` state) | Skills read/write the same JSON/text files |
| `model: github-copilot/claude-haiku-4.5`, `temperature: N` | `model: haiku\|sonnet\|opus\|inherit`; **no temperature** | Determinism becomes a prompt-level instruction; `effort` is the nearest knob |
| `<promise>COMPLETE</promise>` | Subagent's final message is returned automatically | Keep as a textual convention if desired |

## 4. The key architectural change: flatten the router layer

**Constraint (verified):** In Claude Code, *subagents cannot spawn subagents — only the main thread can.* OpenCode's three-level chain `primary → router → specialist` (which works because primaries and routers both have `task: true`) **cannot be reproduced as-is.**

**Resolution:**

- **Primaries → slash commands.** `/builder`, `/planner`, `/toolkit` prime the **main thread** with the persona + startup sequence. The main thread is the only context that can spawn subagents, which is exactly what an orchestrator needs.
- **Routers → routing logic inside the workflow skills.** The six routers (`Concepture-Developer`, `-Quality`, `-Tester`, `-Critic-Source`, `-Critic-Tests`, `-Data`) stop being agents. Their job — *read the project Specialists block, pick the right specialist, dispatch with the right context block* — moves into the `prd-workflow` / `adhoc-workflow` skills, executed by the main thread. The main thread invokes the **specialist subagents directly** (`react-dev`, `react-critic`, …).
- **Specialists & critics stay subagents.** They still run in isolated context; only the dispatch indirection is removed.

Net effect: `main-thread(/builder) → specialist subagent`. Two levels instead of three. Context isolation where it matters is preserved; the Specialists-block-driven, non-hardcoded routing contract is preserved (now as skill instructions rather than a separate agent).

**Optional polish:** a `SessionStart` hook (`hooks/hooks.json`, using `${CLAUDE_PLUGIN_ROOT}`) can print a one-line greeter telling the user to run `/builder`, `/planner`, or `/toolkit` — approximating OpenCode's `default_agent` boot without hijacking the session.

## 5. Frontmatter translation rules (agents)

OpenCode boolean tool-map → Claude Code `tools` allowlist; model remap; drop `temperature`.

**Tool map:**

| OpenCode | Claude Code tool(s) |
|---|---|
| `read: true` | `Read, Grep, Glob` |
| `edit: true` | `Edit, Write` |
| `bash: true` | `Bash` |
| `webfetch: true` | `WebFetch` |
| `todowrite: true` | `TodoWrite` |
| `task: true` | *(omit — not grantable to subagents; orchestration is main-thread only)* |

**Model map:** `github-copilot/claude-haiku-4.5` → `haiku`; `github-copilot/claude-sonnet-4.5` → `sonnet`; "global default" (primaries) → `inherit` (or `opus`).

**Temperature:** removed. For the temp-0.0 critics, add a prompt line: *"Be deterministic; report only what you can substantiate from the code — do not speculate."* (`effort` is the nearest available knob if needed.)

**Example — `react-critic` (before → after):**

```yaml
# OpenCode (.opencode/agents/react-critic.md)
---
description: React/JS source file review …
mode: subagent
model: github-copilot/claude-haiku-4.5
temperature: 0.0
tools: { read: true, bash: true }
---
```

```yaml
# Claude Code (.claude/agents/react-critic.md)
---
name: react-critic
description: React/JS source file review (.js, .jsx, .ts, .tsx — excluding tests). Use after implementation to review source changes.
model: haiku
tools: Read, Grep, Glob, Bash
---
# (body unchanged; add the determinism line noted above)
```

The markdown **body** of every agent ports essentially verbatim — only frontmatter changes.

## 6. Skill cross-references: drop the `$TOOLKIT_ROOT` path-read pattern

In OpenCode, agents load skills with `read` on `$TOOLKIT_ROOT/skills/<name>/SKILL.md` because OpenCode doesn't auto-discover global skills. **Claude Code does** — plugin skills are auto-discovered by `description` and invoked via the Skill tool (namespaced `concepture-toolkit:<skill>`).

Conversion rules for skill/command bodies:
- Replace *"call the `read` tool on `$TOOLKIT_ROOT/skills/X/SKILL.md`"* with *"invoke the `X` skill"* (model-invocation) — or, where a hard file path is genuinely needed, `${CLAUDE_PLUGIN_ROOT}/skills/X/SKILL.md`.
- Skill **frontmatter** is already compatible: skills use `description` (present in all 35). Add a `name:` only if you want to pin the invocation name; otherwise the directory name is used. Optionally add `allowed-tools`.
- For files that must be read by path (schemas, templates, reference/AGENTS.md), use `${CLAUDE_PLUGIN_ROOT}/...`. For **persistent per-project state**, keep writing to the project's `docs/` (unchanged) — never `${CLAUDE_PLUGIN_ROOT}` (it's a versioned cache that changes on update).

Most skills are workflow prose and port with only these path substitutions.

## 7. Per-project pieces (gather)

1. **Specialists** — convert `.opencode/agents/{react-dev, swift-dev, web-dev, react-critic, swift-critic, web-critic, react-tester, web-quality}.md` → `.claude/agents/*.md` using the §5 rules. (Going forward, new projects get these from the plugin's `project-bootstrap` skill, which copies from bundled `templates/`.)
2. **CLAUDE.md vs AGENTS.md** — gather has both a short `CLAUDE.md` (generic guidelines) and a long `AGENTS.md` (Specialists block + Agent-Models table + git workflow + memory rules). Recommended: make `CLAUDE.md` the auto-loaded entry point and either (a) merge the Specialists block into it, or (b) keep `AGENTS.md` as the data file the Builder skill reads explicitly. Pick one to avoid drift.
3. **MCP** — `opencode.json`'s context7 → `.mcp.json` (project-level) or bundle in the plugin's `.mcp.json`. Remote server, one JSON block.
4. **State files** — `docs/prd.json`, `docs/prd-registry.json`, `docs/session-state/*`, `docs/session-locks.json`, `docs/progress.txt` need **no changes**; the ported skills read/write them identically.

## 8. Phased execution

**Phase 0 — Scaffolding (small)**
- Create `Concepture-toolkit/.claude-plugin/marketplace.json` and `plugin/.claude-plugin/plugin.json`.
- `claude plugin validate` / `/plugin validate`; `/plugin marketplace add <local path>`; install; confirm an empty plugin loads.

**Phase 1 — One vertical slice (proof of the flattened model)**
- Port: `/builder` command (startup + dispatch), `adhoc-workflow` skill (with routing logic inlined), `session-setup` + `session-state` + `builder-dashboard` skills, `explore` agent, and gather's `react-dev` + `react-critic` specialists.
- Run `/builder` on a trivial ad-hoc task; confirm: dashboard renders → Explore runs → react-dev subagent implements → react-critic reviews → session-state & progress.txt written → human gate. **This validates the whole architecture before bulk work.**

**Phase 2 — Bulk agent + skill port**
- Convert remaining global agents (critics, analyzers, toolkit-author/critic) and all remaining skills (prd-workflow, conventions-*, project-*, toolkit-*, dashboards, etc.).
- Convert `/planner` and `/toolkit` commands.
- Bundle `schemas/`, `templates/`, and `reference/{AGENTS.md, TOOLKIT-CONVENTIONS.md}`.

**Phase 3 — Per-project finalize (gather)**
- Port the remaining 6 specialists; reconcile CLAUDE.md/AGENTS.md; move context7 to `.mcp.json`.
- Update `project-bootstrap` to write specialists into `.claude/agents/` (from templates) instead of `.opencode/agents/`.

**Phase 4 — Launcher decision & cleanup**
- Decide the fate of `concepture-opencode`: drop it (just `cd && claude`), or keep a thin `concepture-claude` wrapper for the env-file load + project picker. The `envFile` sourcing is the one piece with no native CC equivalent worth preserving.
- Optionally add the `SessionStart` greeter hook.

**Phase 5 — Verify & document**
- End-to-end PRD run + ad-hoc run in gather. Confirm parity with OpenCode behavior. Update the toolkit README with `/plugin` install/enable instructions.

## 9. Open decisions

1. **Coexistence** — plan assumes parallel (keep `.opencode/` working). Confirm, or commit to retiring OpenCode after Phase 5.
2. **Marketplace location** — local path in the toolkit repo (assumed) vs. push to GitHub and install via `owner/repo` shorthand (enables multi-machine sync).
3. **Routers** — confirmed flatten-into-skills (recommended). Alternative (keep them as thin "advisory" agents that only *return* a routing decision to the main thread) is possible but adds a round-trip for no isolation benefit.
4. **CLAUDE.md vs AGENTS.md** — choose merge vs. keep-as-data-file (§7.2).
5. **Determinism** — accept prompt-level determinism for critics (no `temperature`), or experiment with `effort` settings.
6. **Launcher** — drop entirely vs. keep a thin env-file wrapper (§Phase 4).

---

## 10. Risks / watch-items

- **Nesting**: any skill instruction that says "the router dispatches to…" must be rewritten so the **main thread** dispatches. Audit all 35 skills for router-as-agent assumptions during Phase 2.
- **Path references**: `$TOOLKIT_ROOT` appears throughout skill bodies — every occurrence must become a skill invocation or `${CLAUDE_PLUGIN_ROOT}`. Grep the toolkit for `TOOLKIT_ROOT` and `~/.config/opencode` before declaring a skill ported.
- **Plugin cache is versioned**: never write state under `${CLAUDE_PLUGIN_ROOT}`; project `docs/` remains the state home.
- **Namespacing**: plugin skills invoke as `concepture-toolkit:<skill>`; update any user-facing references.
- **Model parity**: haiku-4.5/sonnet-4.5 map to `haiku`/`sonnet` aliases (latest of that tier) — confirm that's acceptable vs. pinning full model IDs.

## 11. Quick reference — install & toggle (once built)

```bash
# Add the local marketplace (from the toolkit repo root)
/plugin marketplace add ~/Documents/GitHub/Concepture-toolkit

# Install + enable
/plugin install concepture-toolkit@concepture

# Toggle off / on later
/plugin disable concepture-toolkit@concepture
/plugin enable  concepture-toolkit@concepture

# Then, in any project:
/builder        # or /planner, /toolkit
```
